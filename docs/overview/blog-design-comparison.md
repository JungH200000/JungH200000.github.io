## 1. 비교 범위와 방법

이 문서는 두 저장소의 현재 소스와 `website_blog/docs/design/qa/screenshots`에 보관된 데스크톱·모바일 화면을 함께 비교한 결과다. 레퍼런스 파일은 구현 결과의 정답 화면이 아니라 어떤 원칙을 선택했는지 판단하는 기준으로 사용했다.

새 빌드를 실행해 캡처한 것은 아니며, 저장된 QA 화면은 2026-08-05 구현 상태를 보여 준다. 글 수처럼 변할 수 있는 값은 2026-08-07 현재 소스에서 다시 계산했다.

## 2. 한눈에 보는 결론

`website_blog`는 **Hashnode의 정보 구조와 Notion의 편집 톤을 결합한 읽기 중심 아카이브**다.

- Hashnode에서 가져온 요소: 고정 좌측 탐색, 2열 카드 피드, 얇은 테두리, `#1d52de` 단일 파란 포인트, 작은 대문자 레이블
- Notion에서 가져온 요소: 따뜻한 종이색 배경, Inter 계열 서체, 넓은 여백, 강한 제목 대비, 문서처럼 차분한 본문
- 별도로 확장한 요소: 다크 모드, 계층형 카테고리, 글 정렬, 본문 목차, 코드 복사, Mermaid, 이전·다음 글과 관련 글

현재 프로젝트는 **Minimal Mistakes 기반의 전통적인 개인 기술 블로그**다. 상단 메뉴, 작성자·카테고리 사이드바, 텍스트 목록, 본문 우측 목차가 익숙하고 기능적으로 안정적이지만, 화면 위계와 반응형 표현은 `website_blog`보다 오래된 인상을 준다.

## 4. 레퍼런스가 구현에 반영된 방식

### 4.1 Hashnode에서 직접 이어진 부분

| Hashnode 레퍼런스 | `website_blog` 구현 | 반영 정도 |
| --- | --- | --- |
| Blueprint Blue `#1d52de` | `--primary`, `--primary-fill`에 동일 값 사용 | 직접 반영 |
| Ink Black `#16191c` | `--ink`에 동일 값 사용 | 직접 반영 |
| 240~280px 고정 좌측 사이드바 | 236px `category-sidebar` | 거의 동일 |
| 1200px 콘텐츠 폭 | 1180px `--container` | 거의 동일 |
| 2열 카드 피드 | `.post-grid`의 2열 배치 | 직접 반영 |
| 그림자보다 1px 테두리 | 카드·사이드바·헤더에 `--hairline` 사용 | 직접 반영 |
| 활성 항목의 파란 좌측 표시 | 사이드바 활성 항목에 3px 파란 표시 | 직접 반영 |
| 10~18px의 제한된 모서리 체계 | 6·10·12·16px 토큰 사용 | 조정 반영 |

그대로 복제하지 않은 부분도 있다. 커뮤니티 서비스에 필요한 투표·댓글 수, 작성자 행, 로그인 CTA, 카드 썸네일은 개인 개발 기록 아카이브의 핵심이 아니어서 제외됐다. Hashnode의 큰 일러스트형 히어로 대신 첫 번째 글 카드를 넓게 강조한다.

### 4.2 Notion에서 이어진 부분

| Notion 레퍼런스 | `website_blog` 구현 | 반영 정도 |
| --- | --- | --- |
| Warm Paper `#f6f5f4` | `--canvas: #f7f7f5` | 매우 유사 |
| NotionInter와 강한 제목 대비 | Inter/Pretendard, 큰 제목과 음수 자간 | 대체 서체로 반영 |
| 넓은 여백으로 섹션 구분 | 홈 섹션 56~112px, 글 본문 상하 여백 확대 | 직접 반영 |
| 카드의 12px 모서리 | `--radius-lg: 12px` | 직접 반영 |
| 흰 표면과 따뜻한 배경의 미세한 대비 | `#fbfbfa` 표면과 `#f7f7f5` 배경 | 직접 반영 |
| 단일 구조색 + 장식색 분리 | 구조색은 파랑으로 제한 | 원칙 반영 |

Notion의 마케팅 요소는 대부분 사용하지 않았다. 스티커 팔레트, pill 형태 CTA, 짙은 인디고 히어로 밴드, 다단 마케팅 섹션은 개발 글 탐색을 늦출 수 있어 구현에서 빠졌다. 따라서 구현 블로그는 Notion의 외형을 복제하기보다 **문서성, 여백, 타이포그래피 규율**만 채택했다.

### 4.3 두 레퍼런스와 다른 독자적인 결정

- 상단 헤더와 좌측 사이드바를 함께 사용해 검색·테마 전환은 전역 헤더, 분류 탐색은 사이드바에 분리했다.
- 첫 글만 전체 폭으로 강조하고 나머지를 2열로 배치해 최신 글의 우선순위를 만들었다.
- `type`과 최대 2단계 `categoryPath`를 트리로 표시해 많은 기술 글을 계층적으로 탐색할 수 있게 했다.
- 글 본문은 760px 읽기 폭, 별도 목차, breadcrumb, 관계 기반 관련 글을 제공한다.
- 레퍼런스가 라이트 중심인 것과 달리 동일 토큰 구조로 다크 모드를 제공한다.

## 5. 화면별 비교

### 5.1 홈

현재 프로젝트 홈은 166개 글을 안정적으로 페이지에 나눠 보여 주고 카테고리별 누적량도 즉시 확인할 수 있다. 반면 한 행에 제목과 날짜 중심으로만 표시되어 글의 내용 차이와 우선순위가 약하다. 넓은 빈 공간에 비해 실제 정보 밀도도 낮다.

`website_blog` 홈은 유형, 날짜, 제목, 180자 이내 설명, 태그를 카드 하나에 묶고 첫 글을 크게 표시한다. 독자는 글을 열기 전에 성격을 판단할 수 있다. 다만 현재는 공개 글이 3개뿐이므로, 166개 규모가 되면 전체 글·카테고리·검색 결과의 정적 페이지네이션과 필터 상태 유지가 필요하다.

### 5.2 글 상세

현재 프로젝트의 장점은 오래된 글에서도 고정 목차, 이전·다음 글, 관련 글이 이미 작동한다는 점이다. 기술 글이 길어질수록 이 구조는 유효하다. 다만 제목과 본문이 작고 화면 좌우 보조 영역이 강해 본문 집중도가 상대적으로 낮다.

`website_blog`는 제목과 설명을 넓은 상단 헤더에서 먼저 보여 주고, 본문은 760px로 제한한다. 좌측 목차와 본문 사이 간격도 넓어 읽기 흐름이 명확하다. 모바일에서는 목차를 본문 앞의 카드로 바꿔 숨기지 않고 접근성을 유지한다.

### 5.3 탐색과 상호작용

- 현재 프로젝트: Home/About/GitHub, Lunr 검색, 7개 카테고리, 페이지네이션, Utterances 설정, RSS, 이전·다음·관련 글
- `website_blog`: 검색, 다크 모드, 유형+중첩 카테고리, 태그, 정렬, RSS, 이전·다음·관련 글, Giscus 준비 상태

기능 수만 보면 둘 다 개인 기술 블로그에 필요한 핵심을 갖춘다. 차이는 `website_blog`가 탐색 상태와 글 메타데이터를 화면 위계로 더 적극적으로 드러낸다는 점이다.

## 6. 유지할 점과 주의할 점

### `website_blog`에서 유지할 점

- 종이색 배경, 단일 파란 포인트, 얇은 테두리의 제한된 토큰 체계
- 첫 글 강조와 나머지 2열 카드라는 점진적 위계
- 프로필, 글 유형, 하위 카테고리, 태그를 분리한 탐색 구조
- 본문 폭, 목차, breadcrumb, 글 관계 탐색
- 390px 화면에서 가로 넘침 없이 재배치되는 모바일 구조

### 현재 프로젝트에서 보존할 가치가 있는 점

- 166개 글을 이미 처리하는 페이지네이션
- 긴 글에서 검증된 고정 목차
- 기존 permalink와 카테고리 URL이 축적한 링크 안정성
- 이전·다음 글, 관련 글, RSS와 댓글 연결 방식

### 규모 확장 시 주의할 점

`website_blog`를 현재 프로젝트의 실질적인 후속 사이트로 사용한다면 디자인보다 먼저 목록 규모를 해결해야 한다. 166개 글을 한 번에 카드로 렌더링하지 않도록 전체 글·유형·카테고리에 동일한 페이지 크기와 URL 규칙을 적용하고, Pagefind 결과에도 더 보기나 필터를 제공해야 한다. 기존 permalink를 바꿀 경우에는 리디렉션 표도 별도로 관리해야 한다.
