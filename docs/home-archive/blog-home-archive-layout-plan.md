## 1. 목표와 결론

향후 홈과 아카이브를 변경한다면 같은 글을 보여 주더라도 목적을 분리하는 것이 좋다.

- **홈**: 이 사람이 무엇을 공부했고, 어떤 글을 먼저 읽어야 하며, 얼마나 꾸준히 기록했는지 10초 안에 전달한다.
- **아카이브**: 166개 글에서 원하는 시기·카테고리·주제를 빠르게 찾게 한다.

핵심 원칙은 **상단에서 대표성과 실력을 보여 주고, 하단에서 양과 지속성을 증명하는 것**이다. 현재 프로젝트의 축적 신호는 유지하고, `website_blog`의 카드 위계와 설명 중심 표현만 선택적으로 적용한다.

```mermaid
flowchart LR
  A[방문] --> B[상단: 누구인지 파악]
  B --> C[대표 글: 실력 확인]
  C --> D[최근 기록: 현재 활동 확인]
  D --> E[카테고리·아카이브: 꾸준함 확인]
  E --> F[글 상세 또는 GitHub로 이동]
```

## 2. 현재 콘텐츠를 이용한 홈의 핵심 신호

2026-08-07 현재 원문 기준으로 다음 값이 있다.

| 신호 | 현재 값 | 홈에서의 역할 |
| --- | ---: | --- |
| 전체 글 | 166개 | 꾸준히 기록했다는 가장 직접적인 증거 |
| 기록 기간 | 2025-12-30~2026-08-06 | 단발성이 아닌 지속성 표시 |
| Sprint TIL | 108개 | 일상적인 학습·구현 과정 |
| Weekly Paper | 18개 | 개념을 정리하고 설명한 기록 |
| 프로젝트 글 | 38개 | 초급 12, 중급 15, 고급 11개의 실제 프로젝트 경험 |
| Java 글 | 2개 | 새 학습 영역이 시작된 상태 |

이 숫자는 문구에 직접 고정하지 않고 Liquid의 `site.posts`, `site.categories`에서 계산해 표시하는 것이 안전하다.

## 4. 상단에 들어갈 내용

### 4.1 소개 영역

상단 소개는 자기소개서 전체를 옮기는 곳이 아니다. 다음 세 가지 정보만 남긴다.

1. 이름과 역할 또는 관심 분야
2. 무엇을 기록하는 블로그인지 설명하는 1~2문장
3. About과 GitHub로 이동하는 보조 링크

권장 문구 예시는 다음과 같다.

> 백엔드 개발 과정에서 배운 것과 문제를 해결한 과정, 선택의 이유를 기록합니다.

`현재 공부 중인 기술`처럼 자주 바뀌는 문구는 홈 템플릿에 직접 쓰지 않고 `_config.yml`이나 `_data/profile.yml`에서 관리하는 편이 좋다.

### 4.2 기록 요약

숫자는 장식이 아니라 노력의 범위를 짧게 증명하는 용도로 사용한다.

- 전체 글 수
- TIL 수
- 프로젝트 글 수
- Weekly Paper 수
- 기록 시작일 또는 기간

카테고리 7개를 모두 같은 크기의 숫자 카드로 만들면 상단이 대시보드처럼 보일 수 있다. 상단에는 3~4개의 큰 묶음만 사용하고, 세부 카테고리는 하단 탐색 영역에서 보여 준다.

### 4.3 대표 글

대표 글은 최신 글 자동 선택이 아니라 직접 고른 3개를 기본으로 한다.

| 슬롯 | 보여 줄 역량 | 현재 콘텐츠 예시 |
| --- | --- | --- |
| 1 | 프로젝트 전체를 설명하는 능력 | `MOPL 프로젝트 회고록` |
| 2 | 문제를 분석하고 검증하는 능력 | 배치·Kafka·Redis·SSE 등의 대표 트러블슈팅 |
| 3 | 개념을 자기 언어로 설명하는 능력 | 대표 Weekly Paper 또는 학습 글 |

같은 프로젝트 글만 세 개 선택하면 활동 폭이 좁아 보일 수 있다. `프로젝트 회고 + 깊은 문제 해결 + 학습 설명` 조합을 권장한다.

추가할 front matter 예시는 다음과 같다.

```yaml
featured: true
featured_order: 1
featured_label: "프로젝트 회고"
featured_summary: "Playlist·Notification·SSE를 구현하며 내린 선택과 결과를 정리했습니다."
```

`featured_summary`가 없으면 `excerpt`를 사용하되, 현재 75개 글의 `excerpt`가 비어 있으므로 대표 글에는 반드시 직접 작성한다.

## 5. 하단에 들어갈 내용

### 5.1 최근 기록

최근 기록은 꾸준함과 현재 활동을 보여 주는 영역이다.

- 5~6개만 표시
- 날짜, 카테고리, 제목을 한 행에 배치
- 썸네일은 사용하지 않거나 대표 글에서만 사용
- 대표 글과 중복되는 최신 글은 필요하면 건너뜀
- 마지막에 `전체 아카이브 보기` 링크 제공

이 영역은 카드보다 행 목록이 적절하다. 한 화면에서 여러 날짜를 비교할 수 있어 기록의 연속성이 더 잘 보인다.

### 5.2 카테고리 탐색

하단에서는 기존 사이드바의 7개 카테고리와 글 수를 넓은 화면에서도 확인할 수 있게 한다.

```text
[Sprint TIL · 108] [Weekly Paper · 18]
[초급 프로젝트 · 12] [중급 프로젝트 · 15] [고급 프로젝트 · 11]
[Java 기본 · 1] [객체지향 · 1]
```

각 항목은 기존 카테고리 URL로 연결한다. 카테고리 이름과 URL을 중복 관리하지 않도록 `_data/navigation.yml`을 그대로 재사용하거나 별도 `_data/home.yml`에서 대표 노출 여부만 관리한다.

### 5.3 마지막 행동 경로

홈 마지막에는 선택지를 세 개 이하로 제한한다.

- 전체 아카이브
- 검색
- RSS

About과 GitHub는 상단에 이미 있으므로 반복하지 않아도 된다.

## 6. 아카이브 페이지 권장 구조

현재 `_layouts/posts.html`에는 이미 연도별 그룹과 연도 인덱스가 있다. 이를 독립 `/archive/` 페이지로 노출하고 시각 구조만 정리하는 방식이 가장 안전하다.

### 6.1 데스크톱 와이어프레임

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ARCHIVE                                                                      │
│ 166개의 학습·프로젝트 기록을 연도와 카테고리로 탐색합니다.                  │
│ [검색하기]                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ 카테고리                                                                     │
│ [전체 166] [TIL 108] [Weekly 18] [초급 12] [중급 15] [고급 11] [Java 2]   │
│ 연도  [2026 · 164] [2025 · 2]                                                │
├──────────────────────────────────────────────────────────────────────────────┤
│ 2026                                                       164 posts         │
│ 08.06  Java 기본       글 제목                                 →             │
│ 07.27  고급 프로젝트   MOPL 프로젝트 회고록                    →             │
│ 07.25  고급 프로젝트   트러블슈팅 글                            →             │
│ ...                                                                          │
│                                                                              │
│ 2025                                                         2 posts         │
│ 12.31  Sprint TIL      글 제목                                 →             │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 6.2 아카이브에서 카드보다 행을 권장하는 이유

- 166개 글의 밀도를 유지할 수 있다.
- 날짜와 카테고리를 빠르게 비교할 수 있다.
- 제목이 긴 프로젝트 글도 카드보다 공간을 덜 사용한다.
- 모바일에서도 `날짜 → 카테고리 → 제목` 순서로 자연스럽게 줄바꿈할 수 있다.

설명이 필요한 대표 글은 홈 카드에서 보여 주고, 아카이브는 검색과 이동 속도를 우선한다.

### 6.3 페이지네이션 판단

현재 홈은 `jekyll-paginate`로 5개씩 나뉘지만, `_layouts/posts.html`은 모든 제목을 연도별로 출력할 수 있다. 166개의 **본문이 아니라 제목·날짜·카테고리만** 출력하는 정적 아카이브는 우선 한 페이지로 운영해도 된다.

GitHub Pages의 안전한 플러그인 범위에서 카테고리별 별도 페이지네이션을 추가하는 작업은 단순 CSS 변경이 아니다. 먼저 연도별 한 페이지 + 기존 Lunr 검색을 적용하고, 실제 로딩·탐색 문제가 확인되면 페이지네이션 플러그인 또는 빌드 방식 변경을 검토한다.

## 7. Jekyll/Liquid 구성 예시

### 7.1 첫 페이지에서만 소개와 대표 글 출력

`jekyll-paginate`의 `/page2/` 이후에도 소개 영역이 반복되지 않게 해야 한다.

```liquid
{% if paginator == nil or paginator.page == 1 %}
  {% include home/intro.html %}
  {% include home/stats.html %}
  {% include home/featured-posts.html %}
{% endif %}

{% include home/recent-posts.html posts=paginator.posts %}
```

### 7.2 대표 글 선택

```liquid
{% assign featured_posts = site.posts | where: "featured", true | sort: "featured_order" %}

<div class="featured-grid">
  {% for post in featured_posts limit: 3 %}
    {% include home/featured-card.html post=post %}
  {% endfor %}
</div>
```

### 7.3 통계 계산

```liquid
{% assign total_posts = site.posts | size %}
{% assign til_count = site.categories['Sprint TIL'] | size %}
{% assign weekly_count = site.categories['Sprint Weekly Paper'] | size %}

{% assign basic_count = site.categories['Sprint 백엔드 초급 프로젝트'] | size %}
{% assign intermediate_count = site.categories['Sprint 백엔드 중급 프로젝트'] | size %}
{% assign advanced_count = site.categories['Sprint 백엔드 고급 프로젝트'] | size %}
{% assign project_count = basic_count | plus: intermediate_count | plus: advanced_count %}
```

### 7.4 아카이브 페이지 front matter

```yaml
---
title: "전체 기록"
layout: posts
permalink: /archive/
author_profile: true
sidebar:
  nav: categories
---
```

## 8. 수정 대상 파일

| 파일 | 변경 목적 |
| --- | --- |
| `index.html` | 홈 소개 문구나 홈 전용 옵션 지정 |
| `_layouts/home.html` | 상단 대표 영역과 하단 최근 기록·탐색 영역 배치 |
| `_includes/home/*.html` | 소개, 통계, 대표 카드, 최근 목록을 작은 단위로 분리 |
| `_includes/archive-single.html` | 일반 목록 행의 카테고리·설명 표현 정리 |
| `_layouts/posts.html` | 연도별 아카이브 헤더와 행 레이아웃 정리 |
| `_pages/archive.md` | `/archive/` 진입점 추가 |
| `_data/navigation.yml` | 상단 메뉴에 Archive 추가 |
| `_sass/minimal-mistakes/_archive.scss` | 대표 카드·최근 행·연도별 아카이브 스타일 |
| 대표 글 Markdown 3개 | `featured*`, 읽을 수 있는 `excerpt` 추가 |

새 홈 구성은 현재 permalink나 글 본문을 변경하지 않는다.

## 9. 단계별 적용 순서

### 1단계: 정보 구조만 적용

- Archive 메뉴와 `/archive/` 페이지 추가
- 첫 페이지에만 소개·통계·대표 글 출력
- 최근 글은 기존 pagination을 유지
- 기존 주황색 `plum` 테마는 그대로 유지

### 2단계: `website_blog`의 시각 위계 적용

- 대표 글만 hairline 카드로 표시
- 일반 최근 글은 조밀한 행 목록으로 변경
- 제목·설명·메타데이터의 크기와 간격 정리
- 모바일 한 열 구조 확인

### 3단계: 운영하면서 보완

- 대표 글 교체 규칙 정립
- 검색에서 카테고리 필터가 실제로 필요한지 확인
- 아카이브 한 페이지의 로딩과 탐색이 불편할 때만 페이지네이션 검토

## 10. 완료 기준

- 첫 화면에서 이름, 블로그 목적, 전체 기록량, 대표 글을 확인할 수 있다.
- 대표 글 3개가 서로 다른 역량을 보여 준다.
- 최근 기록 5~6개에서 날짜의 연속성이 보인다.
- 전체 166개 글과 7개 카테고리로 이동할 수 있다.
- `/page2/` 이후에는 소개·대표 영역이 반복되지 않는다.
- `/archive/`에서 연도와 카테고리를 이용해 글을 찾을 수 있다.
- 390px 화면에서 카드와 목록이 가로로 넘치지 않는다.
- 기존 글 URL과 카테고리 URL이 바뀌지 않는다.

## 11. 최종 권장안

홈은 `포트폴리오형 소개 페이지`와 `최신 글 목록`의 중간 형태가 적절하다. 상단은 대표 글과 기록 요약으로 신뢰를 만들고, 하단은 최근 기록과 전체 아카이브로 꾸준함을 증명한다.

아카이브는 `website_blog`의 큰 카드 피드를 그대로 복제하지 않고 현재 프로젝트의 높은 글 밀도를 보존해야 한다. **홈에는 선별된 카드, 아카이브에는 조밀한 행 목록**을 사용하는 것이 두 프로젝트의 장점을 가장 잘 결합한다.
